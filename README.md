# dsh-title-on-summary

让 DSH 会话标题跟随当前工作：每次上下文压缩产生摘要后，插件根据摘要和最近的用户消息更新会话名称。

例如，会话最初讨论“开发插件”，当前正在处理“标题生成输入预算”时，模型会优先依据当前工作生成标题。实际措辞取决于所配置的模型。

## 安装与开始使用

在 DSH 插件管理中添加仓库地址：

```text
https://github.com/AkezI-T/dsh-title-on-summary
```

也可以添加本地项目目录。仓库附带构建产物，安装时无需先构建。安装后按 DSH 返回的应用状态操作；更新已安装插件后，需要重启 Host 加载新代码。

安装声明默认启用模型生成，并使用 `deepseek-official / deepseek-flash`。使用前确认这条路由已在 DSH 中配置，或将 `llm.provider`、`llm.model` 改为可用的路由。希望只在本地处理时，将 `titleSource` 设为 `local`。

## 标题如何生成

插件只响应已产生的 `compaction/summary` 事件，每次事件最多发起一次辅助模型请求。处理顺序如下：

1. **模型生成**：将摘要和最近三条真实用户消息交给辅助模型，生成一行标题。
2. **本地派生**：模型服务缺失、路由未填、超时、请求失败或返回不可用内容时，从文本派生标题。`titleSource: local` 直接使用此路径。
3. **保留原标题**：无法派生标题时跳过改名。新旧标题相同时也跳过写入；改名失败记录 warning，不向会话抛出异常。

两条路径共用 `maxLength`，默认 32 字符，超长时优先在标点或空格处截断。宿主还会按自身规则规范化标题。

### 模型优先读取当前工作

送入模型前，插件扫描完整摘要，把有正文的小节按以下顺序移到前部，再追加其余摘要内容：

| 顺序 | 英文小节 | 中文小节 |
|---|---|---|
| 1 | `Current Work` | `当前工作`、`当前进度`、`进行中` |
| 2 | `Next Step` | `下一步` |
| 3 | `Pending Jobs` | `待办`、`待办任务` |

小节需要使用 Markdown 标题；代码围栏内的标题不参与识别。空小节及仅有 `(none)`、`（无）` 等占位内容的小节不会获得优先位置。没有匹配的有效小节时，保留摘要原顺序。

重排后按 UTF-8 字节预算截断，因此长摘要末尾的当前工作也有机会优先进入模型。单个当前工作小节过长时，后续小节仍可能被截断。这个过程只准备辅助请求的输入，会话中保存的摘要保持原样。

### 用户消息决定语言并补充方向

插件只收集真实的 `user/message`，排除压缩产生的 checkpoint 消息。最近三条消息按时间顺序传给模型：

- 标题语言跟随用户消息，避免英文压缩摘要主导中文会话的标题。
- 用户提出具体的新需求时，模型据此调整标题焦点。
- 用户只发送“继续”“好的”等确认语时，提示词要求结合摘要中的当前工作或下一步确定主题。

没有缓存的用户消息时，模型依据摘要及其中的用户引文选择语言。这些是给模型的指令，实际效果仍取决于模型的遵循情况。

本地派生优先取当前工作、下一步或待办小节的第一条有效散文，再退回全文第一条；会跳过 Markdown 标题、表格、代码围栏和占位行。摘要候选与最近用户消息的汉字倾向不一致时，尝试从该用户原文派生。

## 配置

下例与随安装提供的配置一致，可在 DSH 的插件配置中调整：

```yaml
enabled: true
titleSource: llm
maxLength: 32
minLength: 4
llm:
  provider: deepseek-official
  model: deepseek-flash
  maxInputBytes: 4096
  maxOutputTokens: 4096
  timeoutMs: 60000
  targetWords: 5
  targetCjkCharacters: 10
```

| 配置项 | 默认值 | 作用 |
|---|---|---|
| `enabled` | `true` | 关闭后不订阅事件、不注入服务 |
| `titleSource` | `llm` | `llm` 优先调用模型，失败转本地；`local` 只在本地派生 |
| `maxLength` | `32` | 两条路径共用的标题长度上限 |
| `minLength` | `4` | 本地派生时有效散文的最短长度 |
| `llm.provider` / `llm.model` | 安装声明：`deepseek-official` / `deepseek-flash` | 模块自身的空配置默认值为空；两项均非空才会尝试调用，任一留空则转本地 |
| `llm.maxInputBytes` | `4096` | 提示词、摘要、最近用户消息及其标签的 UTF-8 文本总预算 |
| `llm.maxOutputTokens` | `4096` | 模型输出上限；推理模型的思考 token 也可能占用额度 |
| `llm.timeoutMs` | `60000` | 辅助请求的取消信号超时，单位毫秒 |
| `llm.targetWords` | `5` | 提示词中非 CJK 标题的目标词数 |
| `llm.targetCjkCharacters` | `10` | 提示词中 CJK 标题的目标字数 |

输入预算先扣除提示词和最近用户消息，再将余量分配给重排后的摘要。最近消息每条最多 400 字节，合计最多 1200 字节；预算不足以容纳摘要正文时直接转本地。此预算不包含 API 消息封装开销，也不等同于 token 数。

输出 tokens 上限用于限制单次调用；标题目标长度由 `targetWords`、`targetCjkCharacters` 提示，最终由 `maxLength` 截断。输出上限过小可能在标题正文生成前耗尽，进而转入本地派生。

## 标题钉住与现有边界

插件用 `sessionTitle.rename()` 写入标题，宿主将其记为显式改名并钉住，停止后续由用户消息触发的自动标题生成。插件仍会在下一次摘要后更新标题，也会覆盖手动设置的标题。显式刷新标题可以解除钉住；刷新内容由宿主注册的标题 provider 决定。

最近用户消息只缓存在内存中，最多保留 64 个会话，每条最多 500 个 JavaScript 字符单位。Host 重启或插件重载后会重新积累消息。若模型不可用且用户原文只是简短确认语，本地派生的标题质量可能较低。

辅助请求尚未对较新的摘要或手动改名做过期检查，迟到结果可能覆盖较新的标题。超时依赖模型服务响应取消信号；这些边界需要在使用时考虑。

## 开发

需要 Node.js 22.19 或以上版本及 Bash；项目没有运行时依赖。

```bash
bash scripts/build.sh
node --test
```

构建将源码复制为发布入口。现有单测使用假模型服务，不发起真实模型请求；测试通过不代表真实模型的标题质量或 GUI 效果已验证。
